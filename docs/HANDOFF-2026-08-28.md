### Setting the secret — do not use `pbpaste`

Three attempts have now stored the command text instead of the token: two on
2026-08-11, one on **2026-08-28 01:03 UTC** during this session. The stored
value was 49 characters, contained a space, and returned 401. "Copy the token
last" has failed every time it has been tried.

Take the clipboard out of the loop:

```
! read -rs TOKEN && gh secret set GH_STARS_TOKEN --body "$TOKEN" && unset TOKEN
```

Paste at the silent prompt, press enter. Nothing echoes, nothing enters shell
history, and the command text *cannot* be what gets stored because the command
is already running when you paste.

Get a **zero-scope** token from https://github.com/settings/tokens/new — the
workflow reads public star data only.

### Verify before spending a run

`gh secret list` proves a secret exists, not that it is a token:

```bash
V=$(pbpaste)   # or however you hold it — prints no secret material
case "$V" in ghp_*|github_pat_*) echo "prefix ok";; *) echo "BAD PREFIX";; esac
case "$V" in *\ *) echo "BAD: contains a space";; *) echo "no space";; esac
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: bearer $V" \
  -X POST -d '{"query":"{viewer{login}}"}' https://api.github.com/graphql
```

`200` means good. Then dispatch `refresh-data.yml`: a bad secret dies at
~20-26s, a good one runs for minutes.

## 3. Repo discovery — what it is and how to run it

New this session. Finds repos that belong in a landscape report but are missing
from the stars.

```bash
export GITHUB_TOKEN=$(gh auth token)      # .env is dead; this is the way
node scripts/discover.mjs --report <slug> --extra owner/repo,owner/repo
node scripts/discover-summary.mjs         # consolidate all candidates.json
```

Skill: `~/.claude/skills/discovering-repos-to-star/` — invoke it rather than
driving the script cold; it carries the judgement layer.

Design: `docs/superpowers/specs/2026-08-28-repo-discovery-design.md`
Plan: `docs/superpowers/plans/2026-08-28-repo-discovery.md`

### The three states

A report's markdown links every repo it *names*, including ones it names as
missing. Crossing that against the star set gives:

- **held** — starred and covered. Dropped.
- **known-gap** — the report names it, you do not star it. Ranked first: a human
  already judged it in-scope.
- **new** — neither. Judge on the merits.

Getting this wrong is easy and expensive: an earlier draft of the spec dropped
anything the report linked, which would have discarded all 45 of
agentic-terminals' known gaps — the single highest-value set in the data.

### Renames must be resolved before diffing

The GraphQL API follows renames silently. Confirmed live 2026-08-28:
`pvolok/mprocs` → `pvolok/dekit`. Diffing the *queried* name would resurface an
already-starred repo on every run. `resolveRepos()` handles this; do not
"optimize" it away.

## 4. Known limitations of discovery, not bugs

**Relevance scoring reads marketing copy.** It ranked `react/react` at 97 for
the charting report and `pingcap/tidb` at 97 for agent-memory, both on a single
category word ("react", "agentic"). Roughly 70 such hits were dropped by hand
from the 138 that passed the numeric filter.

Do **not** fix this by tightening the vocabulary match. The same looseness is
what surfaced `termio-sh/termio` and `nowledge-co/con-terminal`, two genuinely
new agentic terminals. The judgement layer in `SKILL.md` is the intended fix.

**`known-gap` is near-empty outside agentic-terminals.** 36 of 579 candidates,
because only that report ever had a manual gap analysis. Everywhere else,
discovery leans entirely on search, so recall there is unmeasured — there is no
ground truth for "repos nobody has named yet".

**Candidate output is gitignored** (`reports/*.candidates.*`). It is a working
list, not a deliverable, and regenerates on demand.
