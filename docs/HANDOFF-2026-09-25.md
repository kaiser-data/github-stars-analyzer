## 3. Discovery lessons from this session

Running `node scripts/discover.mjs --report llm-evaluation-tooling --extra …` for a
topic that doesn't have a report yet worked poorly:

- **Keyword search drifted.** The report's vocabulary is about evaluation, so the top 25
  results were eval and observability platforms (openlit, HELM, OneUptime), not
  classifiers.
- **`--limit` pushed out the `--extra` names.** Of the 28 names passed with `--extra`,
  only `katanemo/plano` made the table, and it appeared twice (rows 18 and 19). That
  duplicate row is a small bug in `discover.mjs`. The fix here was to check the extras
  directly with `gh api repos/<name>`.
- **The run overwrote `reports/llm-evaluation-tooling.candidates.{md,json}`.** Those
  files are gitignored and regenerated on every run, so nothing was lost. Still, running
  discovery against a borrowed report replaces that report's candidate list.

**Rule:** for a new topic, write the report first, or check the extras by hand. The
skill already says "no report → no discovery", and this session is why that rule exists.

This is also the strongest application found for Jev. `discover.mjs` scores relevance
by vocabulary overlap, which is how `dotnet/runtime` scored 60+ for agent runtimes. A Jev
yes/no check per candidate ("does this belong in the <report> landscape?") would target
exactly that weakness. A full pass over all stars is about 1M input tokens, roughly $0.04
at list price. See §5.
