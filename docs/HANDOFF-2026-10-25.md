## 2. Hosting: Netlify → Vercel

- **Vercel project:** `star-astrolab`, team `martinkaiserai-2420s-projects`, linked locally in `.vercel/`
  (gitignored).
- **`vercel.json`:**
  - `buildCommand` runs `npm run build`, then swaps the files: `dist/index.html` becomes `app.html` and
    `landing.html` becomes `index.html`. Vercel serves real files before rewrites, so the landing page has to
    *be* `index.html`. A rewrite to it would never be reached.
  - SPA fallback: everything except `api/`, `assets/`, `data/`, `reports/` and `prompts/` is rewritten to
    `/app.html`.
  - Caching: `/assets/*` immutable; data, reports and prompts cached for 1h with stale-while-revalidate.
- **`.vercelignore`** keeps `.env*`, `src/data`, `graphify-out`, `docs` and `.netlify` out of the CLI
  upload. Without it the CLI would upload `.env`.
- **Ask AI function:** it now lives in `api/ask.mjs`, with `export const POST = handler` and **no default
  export**. With a default export, Vercel treats the file as a Node `(req, res)` handler and the call fails
  with `FUNCTION_INVOCATION_FAILED`. `netlify/functions/ask.mjs` is a 3-line re-export, kept until Netlify
  is retired.
  - `includeFiles` bundles `public/data/graph-context.json`. On Netlify that file was never bundled, so the
    function silently fell back to an empty context.
- **Env vars:** Netlify's API showed no LLM key at site or account level, so `ZAI_API_KEY` and `LLM_MODEL`
  were set on Vercel production from the local `.env`, as sensitive. The key works, but **Z.AI returns
  "Insufficient balance or no resource package"**. Ask AI fails until the plan is topped up. The pre-cached
  questions in `questions.json` still answer.
- **Netlify:** `stop_builds: true` is set on `star-astrolab` (site `e14c8511…`). Its last deploy (`8e73495`)
  is still served. `.netlify/state.json` points at an older site id (`037c529d…`, named `hot-repos`). Its
  deploy list mirrors `star-astrolab`, but updating it returns `Unauthorized`.
- **Deploying right now:** `vercel deploy --prod --yes` from the repo root. `vercel git connect` failed:
  *"You need to add a Login Connection to your GitHub account first."*

## 3. Styling and performance

- **Theme:**
  - `tailwind.config.js` overrides `gray` with a neutral near-black scale (900 `#0a0a0a`, 800 `#1a1a1a`,
    700 `#2e2e2e` …) and `blue` with Vercel blue (600 `#0070f3`).
  - Fonts are Geist and Geist Mono via `@fontsource-variable/*` (new dependencies).
  - Tailwind-gray hex codes in the SVG and inline styles were mapped to the same scale.
  - The tab bar uses an underline for the active tab and is sticky. Primary buttons are white on black. The
    top nav is now just the brand plus "About". It used to repeat the tabs, with "Map" always shown active.
  - `src/GitHubStarsAnalyzer.jsx` was left alone. It isn't imported anywhere (dead code).
- **First paint:** the `inline-critical-css` plugin in `vite.config.js` replaces the stylesheet link with an
  inline `<style>` (about 30 KB raw) and preloads the Latin Geist woff2.
- **Scrolling:** `.cv-auto` is on the Browse cards (2,408 of them), `.cv-children` on report sections, and
  `.layer` on the detail drawer and the Browse list (`src/index.css`).
- **3D views (`MapView.jsx`, `TopicMap.jsx`):**
  - The biggest win was memoising the accessors (`nodeThreeObject`, `nodeColor`, `linkColor`, particles,
    handlers). react-force-graph re-applies any accessor whose identity changes, and each hover was
    rebuilding about 400 label textures.
  - Labels have `raycast = () => {}`, so hover picking skips them.
  - The WebGL clear colour is opaque `#050505`; it used to be a transparent canvas over a CSS gradient.
  - No `backdrop-blur` over the animated canvas or on the sticky tab bar.
  - Topics draws links with `linkWidth={0}` (lines, not cylinder meshes) and caps the pixel ratio at 1.5.
- **Risk chart:** the circles are built in a `useMemo` with one delegated listener on the `<g>`, so a mouse
  move re-renders only the tooltip.
- **Not verified in a browser:** headless Chrome hangs on the WebGL tabs, so the Map and Topics changes were
  only build-checked. Risk and Browse were screenshot-checked. If the map still stutters with the full corpus
  showing, the next step is an `InstancedMesh` for the nodes (one draw call instead of one per node).

## 6. Ask AI on Nebius, with a spend cap

- **Provider:** Nebius Token Factory (`https://api.tokenfactory.nebius.com/v1`). The model is
  `Qwen/Qwen3-235B-A22B-Instruct-2507`, a non-reasoning model, so it doesn't spend its budget thinking and
  return empty content.
  - Price: $0.20 in / $0.60 out per 1M tokens, read from `/v1/models?verbose=true`.
  - The key is the one from `research/do-models-have-minds/.env`. `ZAI_API_KEY` was removed from Vercel.
- **Cap:** `scripts/lib/spend-budget.mjs`, set to `BUDGET_DAILY_USD=1` and `BUDGET_WEEKLY_USD=5`.
  - Each request reserves its worst case (prompt estimate + `max_tokens`) in Redis before calling the model,
    and refuses with `code: budget` (HTTP 429) if either cap would be crossed.
  - When the stream ends, the reservation is replaced with the real cost from `stream_options.include_usage`.
  - Counters are integer micro-dollars, in keys `ask:spend:day:<date>` and `ask:spend:week:<monday>` (UTC).
- **It fails closed:** with no reachable Redis, every request is refused with `code: budget_store`.
- **Store:** Upstash Redis `star-astrolab-spend` (free tier, eu-central-1, id `2a3192d9…`). It was created
  through the Upstash Developer API, because the Vercel marketplace install kept stopping at "accept terms".
  `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` (sensitive) are set on Vercel production. The
  management credentials (`UPSTASH_EMAIL`, `UPSTASH_API_KEY`) are in the local `.env` only.
  - Sensitive Vercel env vars can't be read back with `vercel env pull`. To inspect the counters, get the
    REST token from `GET https://api.upstash.com/v2/redis/database/<id>`.
- **Verified live (2026-10-25):** one question went through Nebius and the counter settled to 294 µ$
  ($0.000294), down from a hold of about $0.0015.
- To change the caps or the model, edit the Vercel env (`BUDGET_*`, `LLM_MODEL`, `LLM_PRICE_*`) and
  redeploy. Keep the prices in step with the model, or the counter will be wrong.
