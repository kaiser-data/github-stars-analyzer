Silverblock · OpenClaw 2.0 vs Hermes
19 September 2026 · primary docs + dataset, not a recap blog

Two 24/7 agents, sixteen categories

OpenClaw 2.0 is a shared gateway that people join. Hermes is a persistent agent that writes its own skills. The old “orchestration vs learning” split is stale; both now do both. The remaining split is still real.

The split that still holds

Pick OpenClaw 2.0 when several humans must share one assistant, one session, and one routing plane (Telegram in, Control UI out, cloud worker in the middle). Pick Hermes when the long-lived thing is the agent itself: memory that curates, skills it writes, bots with separate souls, execution that can jump to Docker/SSH/Modal.

OpenClaw 2.0

Gateway owns state. v2026.8.1 (30/31 Aug 2026) is the 2.0 name; ship current stable 2026.9.x. Foundation, no first-party paid host. TypeScript / Node. Already Silver Parrot.

Hermes Agent

Agent owns the loop. Nous Research, MIT, Python. Installer + linger for 24/7. Bot Mode, skill_manage, FTS5 session search, hermes claw migrate. First-party Portal and Cloud exist.

1. Identity and positioning

Both are self-hosted, model-agnostic, always-on assistants with a gateway, skills, memory, and chat channels. They advertise different centres of gravity.

OpenClaw

Gateway-first, now multiplayer

Official line: an assistant that runs on your hardware and meets you in the channels you already use. 2.0’s own post (Rudolph, 30 Aug) frames growth as “one useful workflow → more places → share the session with another person.” Shared cloud sessions exist because the team building OpenClaw could not hand off a live Claw without losing context.

Hermes

Agent-first, “grows with you”

Official line: a persistent agent that plans, uses tools, and writes SKILL.md from what it just did. Bot Mode is a UI over profiles: each bot is ~/.hermes/profiles/<name>/ with its own role, model, memory, skills, avatar. The primitive is the profile, not the shared session.

Category: different products that overlap. OpenClaw is infrastructure around an assistant. Hermes is an assistant that accretes procedure.

3. Install, VPS, 24/7 daemon

Both are first-class on a Linux VPS. The docs disagree on how much RAM and ceremony you need.

OpenClaw

Onboard a daemon; bind loopback

curl -fsSL https://openclaw.ai/install.sh | bash then openclaw onboard --install-daemon. Official VPS pages: Hetzner Docker (≥6 GB RAM for a source image; prebuilt can be smaller), DigitalOcean, Ansible+Tailscale+UFW, Kubernetes. Gateway owns state. Default: loopback, SSH tunnel or Tailscale Serve. Shared company agent is documented — one trust boundary, business-only, no personal Apple/Google profiles on that box. systemd: Restart=always.

Hermes

One curl; linger for boot

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash. Installs uv, Python 3.11, Node 26, ripgrep, ffmpeg. Non-sudo service user is documented; Chromium system libs are the one root step. hermes gateway install (user service) or sudo hermes gateway install --system. User services need loginctl enable-linger or they die at logout. --skip-browser for a thin VPS. hermes doctor after.

Day-1 convenience: Hermes is shorter. Production VPS map: OpenClaw (provider pages, Ansible, “shared company agent”). RAM: OpenClaw’s 6 GB is a source-build figure; Hermes can skip the browser. Do not compare those two numbers as idle RAM.

4. Channels and always-on messaging

OpenClaw

Channel-first routing

Official: WhatsApp, iMessage, Slack, Teams, Telegram, Discord, Google Chat, Signal, and “20+ more,” plus native apps. 2.0 messaging notes: Telegram/Slack/Discord/native apps keep more of a conversation intact; accepted messages survive managed restarts. Routing is a Gateway job: which agent, which session. That is why a company Telegram bot and a Control UI can share one identity.

Hermes

Gateway as a subsystem

Official messaging docs cover Telegram (auto command menu, topic→skill binding), WhatsApp (bot number vs self-chat, allowlists, mention gates), Discord (skills as application commands, 100-command cap), plus Slack, Signal, email, Home Assistant. Composio (15 Sep 2026, secondary) lists 27+ including Matrix, Mattermost, Teams, LINE, SimpleX, Feishu, WeCom, SMS. Cron jobs can deliver into those channels; in Bot Mode the routine belongs to the bot.

Channel counts in recap blogs disagree and move weekly. Treat “OpenClaw widest native routing” and “Hermes now covers the major apps plus extras” as the durable facts. Verify the live channel list on each project’s docs before you bet a production number.

Winner for org routing (one identity, many surfaces): OpenClaw. Winner for bot-owned cron into chat: Hermes, slightly.

5. Skills and learning

OpenClaw 2.0 — this changed

ClawHub + Skill Workshop

Human-written skills still live on ClawHub; Control UI installs, enables, disables. 2.0 adds Skill Workshop: proposals, checks, decisions, applied history. Background learning can turn corrections and successful procedures into Workshop skills. Modes: auto (default), propose, off. An agent can repair a skill in the same conversation. Learning is now real; it is governed and UI-visible, not the original differentiator Hermes owned alone.

Hermes — still the loop

skill_manage + Skills Hub + /learn

Skills are agentskills.io Markdown. The agent creates/updates/deletes its own via skill_manage (procedural memory). /learn distills sources into a SKILL.md. Skills Hub can pull official Hermes skills, skills.sh, GitHub, URLs, ClawHub, LobeHub, browse.sh. Write-approval gate: skills.write_approval, review with /skills pending|diff|approve. Bundles preload several skills. Discord registers installed skills as slash commands.

Native marketplace: OpenClaw / ClawHub. Portable format + agent-written procedure: Hermes. Both now learn. Hermes still couples learning to memory and profiles more tightly. Recap blogs that say “OpenClaw skills are static” are out of date as of 2.0.

6. Memory

OpenClaw 2.0

Live recall, SQLite transcripts

2.0 moved sessions and transcripts into SQLite (downgrade warning: post-migration sessions vanish on old file-backed releases). Eligible personal Claws can recall relevant context from that agent’s other private conversations, with UI to search, inspect, import, remove. Secondary write-ups (Mem0, 14 Sep) describe live re-injection every turn — fresher, more tokens — plus auto-compaction and a three-phase “Dreaming” consolidation. Plugin memory (one slot) rather than a menu of vendors.

Hermes

Tiny always-on files + FTS5 + plugins

Official: skills vs memory split — memory holds small durable facts always in context; skills hold procedures loaded when relevant. Community/docs describe MEMORY.md and USER.md under ~/.hermes/memories/, deliberately small so the agent curates. Every CLI and messaging session lands in SQLite; FTS5 search does not need an LLM call. Write-approval gate: memory.write_approval. External providers (Honcho, Mem0, Hindsight, others — count from secondary roundups, verify live). /journey is a learning timeline (CLI/desktop, not messaging).

Mid-session freshness / multi-session Gateway: OpenClaw. Cheap long sessions, curated identity, search without a model call: Hermes. Opposite bets, both now serious.

7. Models and providers

Both are model-agnostic. OpenClaw 2.0 onboarding scans for ChatGPT/Claude/Codex logins, API keys, and local Ollama/LM Studio, then verifies the model before saving. Catalog in the Control UI. Hermes: hermes model, OpenRouter, Anthropic, OpenAI, Nous Portal (hermes setup --portal — 300+ models plus Tool Gateway), local llama.cpp/Ollama. Different Bots can pin different models. OpenClaw has no first-party model shop; Hermes does (Portal).

Reuse a subscription you already pay for: OpenClaw onboarding. One bill for models + hosted tools: Hermes Portal. Local-only: both, with different installers.

8. Execution, sandbox, computer use

OpenClaw

Gateway + nodes + cloud workers

Work can stay on the Gateway, run on a paired node (local screen/camera/system.run), or move to a cloud worker while the transcript stays. 2.0: isolated managed browser profile or shared Chrome tabs; Computer Use on paired Macs and explicitly enabled Windows. Sandbox backends exist (Docker, Podman, SSH, OpenShell). Official docs: sandboxing is off by default; the default assumes a trusted operator.

Hermes

Seven terminal backends

Official/secondary consensus: local, Docker, SSH, Singularity, Modal, Daytona, Vercel Sandbox (verify live config). Same agent, different isolation. Default approval mode is smart — low-risk continues, dangerous commands can stop. Container backends can drop capabilities, no privilege escalation, optional read-only root. Computer Use via cua-driver (installer preloads unless --skip-computer-use).

Flexible where code runs: Hermes. Session stays put while execution moves: OpenClaw. Safer defaults on a laptop: Hermes (smart on). Neither is safe unattended with production secrets unless you turn isolation on.

9. Multi-agent

OpenClaw

Agents, bindings, shared sessions

openclaw agents add creates isolated workspaces with routing and auth. Bind a channel to an agent. 2.0 shared cloud sessions: creator, owner, participants, presence, typing, handoff without losing context. Subagents exist for delegated work. The unit humans share is the session.

Hermes

Bot Mode, groups, A2A

A Bot is a profile. Isolated config, memory, skills, credentials, history. Groups: 2–6 bots, multi-round discussion, even across machines — but crossing a gateway is a trust-boundary change and should be an explicit bridge. Subagents for one-off work. A2A to other compatible agents. The unit that persists is the bot.

Several people, one thread: OpenClaw. Several named specialists that keep their own memory: Hermes.

10. UI and human collaboration

OpenClaw 2.0 rebuilt the Control UI as chat-first: files, approvals, terminals, git diffs, dockable browser beside the conversation. Native apps on iPhone, iPad, Android, macOS, Wear OS. Multiplayer dashboards. Hermes Desktop is a first-class peer of the CLI (same core, config, sessions). macOS installer is Apple Silicon only. Bot Mode roster, Star Map / /journey, kanban across profiles. OpenClaw’s browser app is where most people first meet the product; Hermes still feels CLI/desktop-native.

Shared browser control plane: OpenClaw. Native desktop personal agent: Hermes. Mobile reach: OpenClaw today.

11. Security and secrets

OpenClaw

Strong controls, historically a rough year

2.0: approvals stick to request, command, session, and person. Private credential requests: the agent can ask for a secret without putting it in chat or model context. openclaw security audit. One trust boundary per gateway — not hostile multi-tenant. Loopback default on host installs. CVEs earlier in 2026 (token exfil, pairing→admin) were patched; ClawHub now scans. Residual risk OpenClaw itself names: malicious skill install and skill-update poisoning. Sandbox off by default.

Hermes

Conservative defaults, still operator-owned

smart approvals by default. Skills never expose raw secret values to the model; declared env vars passthrough into sandboxes. Memory/skill writes can require approval. DM pairing / allowlists on WhatsApp. Secrets live in ~/.hermes/.env, not in git. Migration from OpenClaw will not move secrets unless you pass --migrate-secrets. Not “zero CVE forever” — just a stricter out-of-box posture.

Defaults on a fresh box: Hermes. Credential-request UX and audit command: OpenClaw 2.0. Finance box: loopback + Tailscale + no public bind, either runtime. Do not expose 18789 or the Hermes gateway.

12. Updates and day-2 ops

OpenClaw versions by date. 2.0 was a seven-week pause after 106 releases in 230 days; 16,977 PRs in the notes. 9.2–9.4 rebuilt the updater (canary, schema fences, rollback). SQLite session migration makes backups mandatory before 2.0/9.x jumps. Silverblock already knows the dual-gateway failure (LaunchDaemon vs openclaw gateway start). Hermes: hermes update prints the matching command for git / Docker / Nix. hermes config migrate after missing config. Smaller release count in the dataset (31 vs 240) — slower cadence, or just different tagging. Both bus factor 1 in the 12 Sep snapshot.

More battle-tested updater (after 9.x): OpenClaw, if you stay current. Less surface to break: Hermes, if you like a quieter tree. Backup before any major: both; OpenClaw 2.0 is the one with a published “you will lose new sessions on downgrade” warning.

13. Hosted money

OpenClaw Foundation: no paid tier, hosted service, or token — you bring a VPS and a model key. Hermes is MIT and free to self-host; Nous sells Portal (model credits + Tool Gateway; published Plus/Super/Ultra tiers in secondary roundups) and Hermes Cloud (per-day compute while running). If you want someone else to run the box, Hermes has a first-party path. If you want zero vendor around the runtime, OpenClaw is cleaner.

14. Moving between them

Hermes ships hermes claw migrate and --dry-run. Official mapping: SOUL.md → ~/.hermes/SOUL.md; MEMORY.md / USER.md merged; workspace and ~/.openclaw/skills → ~/.hermes/skills/openclaw-imports/; models, approvals, browser CDP. Secrets only with --migrate-secrets. OpenClaw 2.0 also documents importing from Hermes the other way. Neither is a lossless identity move: Telegram bot tokens, LaunchDaemon policy, and SP-bridge paths under ~/.openclaw/secrets are operational, not a file copy.

Trying Hermes from an OpenClaw box: the migrate command exists and is conservative about secrets. Silver Parrot as a production identity: still a cutover, even if the score no longer penalises it.

16. Silverblock, specifically

Silver Parrot already is an OpenClaw agent: LaunchDaemon com.silverblock.openclaw-gateway, secrets in ~/.openclaw/secrets, workspace silver-parrot / silverblock-mvp, Telegram, SP-bridge. The VPS target matches OpenClaw’s own “shared company agent” page. Convenience scoring after Claude’s review (migration not in the formula) still had OpenClaw and Hermes tied at 8.8, OpenClaw winning the fit tie-break.

That means: on product merit they are peers. On operations you already paid for, OpenClaw 2.0 on the VPS is the default. Hermes is the A/B if you want Bot Mode specialists, self-written skills, or Python. Use hermes claw migrate --dry-run on a copy, not on production. Do not run both gateways on 18789.
