Move Silver Parrot to OpenClaw 2.0 on a VPS

Not Hermes. Not a second gateway on the Mac. One Gateway, loopback, Tailscale, 2026.9.x.

Decision this runbook executes

OpenClaw 2.0 on a Linux VPS is the runtime. Hermes stays an A/B, not production. The Mac LaunchDaemon is retired only after the VPS answers Telegram and /health.

Do not skip

  • Backup ~/.openclaw before any 2.0/SQLite jump. Post-migration sessions do not exist on old file-backed releases.
  • Never run openclaw gateway start beside an existing supervisor. That is the outage the Mac runbook already names.
  • Never publish port 18789. Loopback + Tailscale Serve or SSH tunnel.
  • Keep commands.restart: false and OPENCLAW_SERVICE_REPAIR_POLICY=external.
  • Do not sign the VPS into personal Apple/Google/password-manager profiles.

1. Backup the Mac (before you touch versions)

STAMP=$(date -u +%Y%m%dT%H%M%SZ)
DEST="$HOME/backups/openclaw-$STAMP"
mkdir -p "$DEST"
# stop nothing yet — copy while the daemon still runs
rsync -aH --numeric-ids ~/.openclaw/ "$DEST/dot-openclaw/"
tar -C "$HOME/backups" -czf "$DEST.tar.gz" "openclaw-$STAMP"
shasum -a 256 "$DEST.tar.gz" | tee "$DEST.sha256"
# copy the tarball off the Mac (another disk, not only Time Machine)
ls -lh "$DEST.tar.gz"

If OpenClaw is still pre-SQLite on this Mac, this tarball is the only way back. 2.0/9.x will migrate sessions; downgrade without it loses new transcripts.

2. Provision and harden the VPS

  1. Create Debian or Ubuntu. Attach your SSH key. Record the public IP.
  2. SSH in. Update. Create a dedicated user if you will not run as root long-term.
  3. Install Tailscale. Join the tailnet. From the laptop, SSH to the MagicDNS name. Only then restrict public SSH to your admin nets (or Tailscale-only).
  4. Cloud firewall: TCP 22 from admin (or none if Tailscale SSH only). No 18789 to 0.0.0.0/0.
ssh root@<vps-ip>
apt update && apt upgrade -y
curl -fsSL https://tailscale.com/install.sh | sh
tailscale up
# on the laptop, confirm:
# ssh root@<magicdns>

3. Install OpenClaw 2026.9.x, not 8.1

2.0 is the name for v2026.8.1. Production should be current stable 2026.9.x (updater/canary repairs). Two supported shapes:

A — Docker (official Hetzner page)

apt-get install -y git curl ca-certificates
curl -fsSL https://get.docker.com | sh
# then follow docs.openclaw.ai/install/hetzner
# bind 127.0.0.1:18789 only
# persist ~/.openclaw + workspace on the host

B — Host install + systemd

curl -fsSL https://openclaw.ai/install.sh | bash
# as the service user:
openclaw onboard --install-daemon
openclaw --version    # expect 2026.9.x
sudo loginctl enable-linger "$(whoami)"   # if user systemd

Gateway config: bind loopback. Token/password set. commands.restart: false. OPENCLAW_SERVICE_REPAIR_POLICY=external so OpenClaw does not fight Docker/systemd.

4. Restore Silver Parrot state

# from the laptop, after the VPS OpenClaw is installed and stopped
rsync -aH --numeric-ids \
  ~/backups/openclaw-*/dot-openclaw/ \
  root@<vps-tailscale>:/root/.openclaw/

# secrets stay chmod 600, outside git
ssh root@<vps-tailscale> 'chmod 700 ~/.openclaw ~/.openclaw/secrets; chmod 600 ~/.openclaw/secrets/*'

# start via the supervisor only
# Docker: docker compose up -d
# systemd: sudo systemctl start openclaw-gateway
# never: openclaw gateway start

Confirm the agent id, workspace silver-parrot (or silverblock-mvp), and Telegram bind. Re-read 1Password into ~/.openclaw/secrets/ if the copy did not include them (it should).

5. Health before you cut Telegram

# laptop
ssh -N -L 18789:127.0.0.1:18789 root@<vps-tailscale>
# other terminal
curl -sS http://127.0.0.1:18789/health
openclaw security audit
openclaw doctor

Open the Control UI through the tunnel. Send a test in WebChat. Do not enable the Telegram account on the VPS until the Mac daemon is about to stop — two gateways, one bot token, is an outage.

6. Cutover (short window)

  1. Announce a 10-minute Telegram pause if anyone else talks to Silver Parrot.
  2. On the Mac: stop the production daemon only. 
    sudo launchctl bootout system/com.silverblock.openclaw-gateway
# confirm nothing on 18789
lsof -nP -iTCP:18789 -sTCP:LISTEN
  3. On the VPS: start the supervisor. Confirm /health.
  4. Bind/enable Telegram on the VPS. Send a message. Confirm it is the VPS (log line, hostname in doctor).
  5. Disable the Mac LaunchAgent so it cannot resurrect: 
    launchctl bootout gui/$(id -u)/ai.openclaw.gateway 2>/dev/null || true
launchctl disable gui/$(id -u)/ai.openclaw.gateway
  6. Leave the Mac daemon plist in place but unloaded until you are sure. Then delete or document it as retired.

7. Aftercare

  • Daily backup of VPS ~/.openclaw (config + workspace + SQLite) off-box.
  • Updates: openclaw update through the same supervisor. Then doctor, security audit, a Telegram ping.
  • Watchdog: if you port gateway-watchdog.sh, keep the daemon_managed() guard. It must not call openclaw gateway start.
  • Hermes A/B: separate OS user, separate port, hermes claw migrate --dry-run on a copy of state. Not on the production token.
