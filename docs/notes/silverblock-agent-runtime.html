How the rating is built

Each axis is 0–10. Cutover and rewrite from OpenClaw are not scored. Hermes is judged as a 24/7 VPS runtime next to OpenClaw, not as a migration project.

Axis Weight What “10” means
Job fit 50% Named 24/7 assistant with channels, memory, a daemon — not a coding TUI and not a swarm framework.
VPS ops 50% Official systemd/Docker path, headless docs, sane loopback defaults, RAM you can rent cheaply.

Gate: a shipped default that binds a secrets-bearing process off loopback cannot score Ops 10. ZeroClaw fails it hardest — verified 21 Sep 2026, its official image bakes allow_public_bind = true and require_pairing = false, answering unauthenticated requests on /api/config, /api/memory and /api/browse. That is a shipped default, not just a sample. Nanobot passes the same gate: its gateway defaults to 127.0.0.1.

Why the order is this order

=1 · 9.3

The top is a real tie, not a tie-break

Both reviewers closed the OpenClaw/Hermes Fit gap, for the same reason: the rationale asserted an identical capability list and then subtracted a point without naming what was missing. With Fit level and Ops level, the standing “higher Fit wins” rule has nothing to separate. Breaking this tie needs operational testing — reconnects, update pain, recovery after reboot — not another pass over the docs.

=3 · 8.5

Nanobot was the worst call in the first pass

It sat last at 4.0 on the claim that you write your own daemon. That was false, and checkably so: the deployment doc installs a systemd user unit, documents linger for logout survival, and defaults the gateway to 127.0.0.1. It now ties ZeroClaw — and passes the loopback gate ZeroClaw fails.

=3 · 8.5

ZeroClaw gained Fit and lost more Ops

Its capability surface was under-rated, so Fit rises. But the security problem is worse than “a sample binds public”: the official image itself ships require_pairing = false, leaving config, memory and browse endpoints unauthenticated on every interface. Do not deploy it as shipped.

5–8

The middle was scored on vibes

PicoClaw, NanoClaw and IronClaw all under-scored on Fit because the first pass judged them by reputation rather than docs — “too thin,” “Claude-tied,” “a WASM sandbox.” All three document identity, memory, channels and scheduling. ElizaOS is the only row that survived untouched, and it is now last.

What “convenient” looks like on the VPS

This ranking does not tell you to stay on OpenClaw because migration is hard. It tells you OpenClaw, ZeroClaw, and Hermes are the three convenient 24/7 VPS runtimes. If you already have Silver Parrot on OpenClaw, staying is still the cheap path — that is operations, not the score.

  1. Debian/Ubuntu, ≥6 GB if building OpenClaw from source (official Hetzner figure); prebuilt image if smaller.
  2. Tailscale first, then restrict public SSH. No gateway port on 0.0.0.0/0.
  3. Docker Compose or Ansible. Gateway on 127.0.0.1:18789. Tunnel or Tailscale Serve.
  4. Backup ~/.openclaw on the Mac. Install 2026.9.x. Restore. Bind Silver Parrot. Stop the Mac daemon so you do not run two gateways.
  5. openclaw security audit. Keep commands.restart: false. Daily config + workspace + SQLite backup.

Independent review

Same brief sent to Claude Code 2.1.278 (OAuth, Silverblock team) and Codex CLI 0.154.0 (gpt-6-astra, read-only sandbox). The Codex run originally died on a usage cap and was re-run on 21 Sep 2026. Both returned revise. Neither accepted the ranking.

Claude Code · revise

Found the rubric contradictions

Stated up front that it had no tools, so it judged internal consistency only: ZeroClaw’s Ops 10 fails the loopback term of its own rubric, Hermes Fit 9 contradicts “same job as OpenClaw,” and an undeclared “treasury-grade” test was scoring rows 4 and 7. All three held up. Its RAM reasoning did not. Full write-up: docs/notes/review-claude.md.

Codex · revise

Overturned three rationales on the facts

Had web access and cited what it read. OpenClaw’s 6 GB is a source-build figure, so Ops should rise rather than fall; PicoClaw documents far more assistant surface than Fit 6 allows; Nanobot ships a systemd installer. Its revised table is the one adopted here. Full write-up: docs/notes/review-codex.md.

Verification · 21 Sep 2026

Six claims re-checked, six held

No score moved on a reviewer’s say-so. Each claim worth a full point was read back against primary docs: Nanobot’s service installer, OpenClaw’s build-RAM wording, ZeroClaw’s container defaults, PicoClaw’s channel and cron surface, IronClaw’s feature list, NanoClaw’s provider support. All six confirmed.

Found in verification

Two things neither reviewer caught

ZeroClaw’s unauthenticated posture is in the shipped image, not merely a sample — a harder finding than either review made. And NanoClaw is not Claude-locked: /add-codex, /add-opencode and /add-ollama-provider are documented, so the lock-in ding that survived both reviews was wrong.
